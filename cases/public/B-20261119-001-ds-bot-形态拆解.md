## 项目身份（避免撞名）

市面存在一个易混淆的命名对：

| 项目 | 组织 / 作者 | 安装包 | 协议 |
|---|---|---|---|
| DeepSeekBot（DSB） | BotHarness | `deepseekbot` | MIT |
| DeepSeek-Bot（ds-bot） | Fei2411 | `ds-bot` | Apache-2.0 |

两者是**独立项目**，宿主均为 DeepSeek Harness（DSH），安装命令与界面不可混用。本条只做形态拆解，不为任一方站台。

## 形态拆解

- **主 Bot 统筹**：默认有高权限的 Chief，用户消息默认由它回复，再按需调度其他 Bot，降低管理复杂度与 token 消耗。
- **长期记忆**：每个 Bot 跨会话保留记忆，以 Markdown 文件落地，可查看文件与修改历史；有单条字符上限，不是无限记忆。
- **群聊接力**：群管理员默认回复，其他 Bot 无新内容时回 `[PASS]` 保持沉默；Bot 之间可 @ 交接任务。
- **执行能力**：以插件形态运行在 DSH 内，可调用本机已安装的编程 Agent（如 Claude Code / Codex）；模型走 DSH 配置的服务商，并非只能调一家。
- **渠道接入**：公开资料称可接微信、飞书、Telegram 等；具体授权需另行配置，本地群聊成功不等于外部平台已连通。

## 设计取舍

- **为什么群聊默认沉默**：多 Bot 参与、多轮讨论都会显著增加 token 消耗，沉默是对成本的机械约束。
- **为什么记忆落文件而非云端**：可核对、可改、数据留在自己的宿主；代价是常开机器与自行维护。
- **代价**：软件免费不等于零成本——模型额度、常开机器、数据安全和外部账号授权都要自己承担。
- **不成立场景**：需要开箱即用 / 多端同步 / 官方兜底时，平替形态的维护成本会反超订阅费。
